# 1. DHCP Fundamentals
 
Background reviewed before building the lab: what DHCP provides, how a client obtains a lease, and where router-based DHCP fits.
 
## 1.1 What DHCP provides
 
DHCP (Dynamic Host Configuration Protocol) gives a client the settings it needs to communicate on a network.
 
| Parameter | Example | Role |
|---|---|---|
| IP address | 192.168.1.25 | Identifies the host at Layer 3 |
| Subnet mask | 255.255.255.0 | Separates the network portion from the host portion (a /24 here) |
| Default gateway | 192.168.1.1 | Next hop for traffic to other networks |
| DNS server | 8.8.8.8 | Resolves domain names to IP addresses |
| Lease duration | 24 hours | How long the client may use the address before renewing |
 
DHCP does not provide internet access. It provides the configuration a device needs to take part in the network.
 
Without DHCP, every device needs these values entered manually. That is error-prone at scale, and an addressing change means touching each device. With DHCP the values are defined once on the server.
 
An address is leased, not permanently assigned. The client renews the lease, and an address that is no longer used can return to the pool.
 
## 1.2 The DORA exchange
 
| Step | Message | Description |
|---|---|---|
| 1 | DHCPDISCOVER | The client has no address and does not know the server, so it broadcasts a request for a DHCP server. |
| 2 | DHCPOFFER | A server with an available address offers it, with mask, gateway, DNS and lease time. |
| 3 | DHCPREQUEST | The client selects an offer. If several servers responded, this tells the others their offers were not chosen. |
| 4 | DHCPACK | The server confirms the lease. The client can now use the configuration. |
 
Mapping to the IOS commands used in this lab:
 
| Command | Effect on the DHCP exchange |
|---|---|
| `ip dhcp pool <name>` | Creates the set of settings the server can offer |
| `network <subnet> <mask>` | Defines the range addresses are offered from |
| `default-router <ip>` | Gateway sent to the client in the offer |
| `dns-server <ip>` | DNS server sent to the client in the offer |
| `ip dhcp excluded-address` | Addresses the server will never offer |
 
## 1.3 Ways a device can get an address
 
| Method | How it works | Typical use |
|---|---|---|
| Static | Administrator enters the address and settings manually | Servers, routers, switches, printers, infrastructure |
| DHCP from a router | The router runs a pool and leases addresses to clients | Home networks and small or medium offices |
| DHCP from a dedicated server | A Windows or Linux DHCP server manages scopes and policy | Enterprise networks |
 
A dedicated DHCP server adds multiple scopes, reservations, exclusions, lease management, DHCP options, failover and central administration. The client exchange is the same.
 
Router-based DHCP was used in this lab to practise the IOS CLI: creating pools, defining networks, excluding addresses, advertising the gateway and DNS, and verifying leases with `show` commands.
 
## 1.4 Why Packet Tracer
 
Packet Tracer provides a simulated Cisco IOS environment without hardware. Configuration errors can be made and corrected with no effect on a production network, for example a shut-down interface, a wrong subnet or a misconfigured pool.
