# 5. Verification
 
## 5.1 Client configuration
 
On PC1: **Desktop → Command Prompt**, then `ipconfig /all`.
 
| Setting | Value |
|---|---|
| IP address | 192.168.1.11 |
| Subnet mask | 255.255.255.0 |
| Default gateway | 192.168.1.1 |
| DNS server | 8.8.8.8 |
| DHCP enabled | Yes |
 
All values matched `LAN-POOL`. PC2 received 192.168.1.12, the next address in the pool.

## 5.2 Connectivity (ping from PC1)
 
| Test | Command | Result |
|---|---|---|
| PC1 to Edge-Router | `ping 192.168.1.1` | Four replies |
| PC1 to ISP-Router | `ping 200.1.1.1` | Four replies |
| PC1 to PC2 | `ping 192.168.1.12` | Four replies |
 
In Packet Tracer the first ping can time out while ARP resolves the destination MAC address, and later pings succeed. This is not a configuration fault.
 <img width="1024" height="559" alt="image" src="https://github.com/user-attachments/assets/0cb78cfd-d4e5-4031-8b32-419dd8446200" />


## 5.3 Bindings
 
**ISP-Router:** `show ip dhcp binding`
 
| Field | Value |
|---|---|
| IP address | 200.1.1.2 |
| Hardware address | MAC address of Edge-Router FastEthernet 0/0 |
| Type | Automatic |
 
**Edge-Router:** `show ip dhcp binding` listed leases for 192.168.1.11 (PC1) and 192.168.1.12 (PC2).
 
Together they show the whole chain: the ISP-Router leased 200.1.1.2 to the Edge-Router, and the Edge-Router leased the LAN addresses to the PCs.

## 5.4 Pool statistics
 
`show ip dhcp pool`
 
| Pool | Leased addresses |
|---|---|
| ISP-POOL | 1 (Edge-Router) |
| LAN-POOL | 2 (PC1, PC2) |
 
Lease counts match the plan, and no unexpected device is consuming addresses.
