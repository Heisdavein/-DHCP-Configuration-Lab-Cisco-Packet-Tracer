# 2. Topology and Addressing
 
The topology and IP plan were written before any device was configured. That gave a defined expected result to compare against during verification.
 
## 2.1 Design
 
DHCP operates in two places:
 
```
ISP DHCP server → Edge-Router (DHCP client) → Edge-Router (DHCP server) → PCs
```
 
| Device | Model | Role | DHCP function |
|---|---|---|---|
| ISP-Router | Cisco ISR 4331 | Represents the ISP | DHCP server for the WAN segment |
| Edge-Router | Cisco 2911 | Represents the customer router | DHCP client on WAN, DHCP server on LAN |
| PC1 | PC | LAN client | DHCP client |
| PC2 | PC | LAN client | DHCP client |
 
**ISP-Router:** static address 200.1.1.1/24 on the WAN-facing interface, with a DHCP pool from which the Edge-Router receives its WAN address.
 
**Edge-Router:** requests its WAN address by DHCP (expected 200.1.1.2) and uses static 192.168.1.1/24 on its LAN interface, which is the PCs' default gateway. Each interface is in a different subnet.
 
**PC1 and PC2:** no static addresses. Expected leases are 192.168.1.11 and 192.168.1.12.
 
## 2.2 Cabling
 
| Link | From | To |
|---|---|---|
| WAN | ISP-Router GigabitEthernet 0/0/0 | Edge-Router FastEthernet 0/0 |
| LAN | PC1 | Edge-Router FastEthernet 0/1 |
| LAN | PC2 | Edge-Router FastEthernet 0/2 |
 
All links are copper.
 
## 2.3 IP address plan
 
| Device / interface | Address | Assignment | Purpose |
|---|---|---|---|
| ISP-Router WAN | 200.1.1.1/24 | Static | ISP gateway |
| Edge-Router WAN | 200.1.1.2/24 | DHCP | Address received from the ISP |
| Edge-Router LAN | 192.168.1.1/24 | Static | LAN default gateway |
| LAN DHCP pool | 192.168.1.11 onwards | Dynamic | Client address range |
| PC1 | 192.168.1.11 | DHCP | First expected client address |
| PC2 | 192.168.1.12 | DHCP | Second expected client address |
| DNS | 8.8.8.8 | DHCP option | Name resolution |
 
**Reserved range:** 192.168.1.1 to 192.168.1.10 is excluded from the pool for infrastructure that may be added later (switch, access point, NAS, printer). Dynamic addresses start at .11, which keeps static and dynamic addresses separate.
 
**Two subnets:** the WAN (200.1.1.0/24) and LAN (192.168.1.0/24) must be different networks because the router connects them. 192.168.1.0/24 is private RFC 1918 space. 200.1.1.0/24 is used only to represent an ISP-facing network in the simulation. A real ISP would assign the customer an address from its own allocation.
 
## 2.4 Build steps
 
1. Created a new blank Packet Tracer project.
2. Added an ISR 4331 and a 2911, renamed `ISP-Router` and `Edge-Router`.
3. Added PC1 and PC2.
4. Connected the WAN link and the LAN links as listed in 2.2.
5. On each PC, opened **Desktop → IP Configuration** and selected **DHCP**. The PCs do not receive an address until the Edge-Router DHCP service is configured.
## 2.5 Layer 1 check
 
Before configuring addresses, the link indicators in Packet Tracer were checked. A red or inactive link is fixed first. Troubleshooting order used throughout the lab:
 
1. Is the cable connected?
2. Are the router interfaces up?
3. Are the interfaces configured for the correct networks?
4. Can the devices communicate?
5. Is DHCP configured correctly?
6. Is the correct address being assigned?
7. Are the gateway and DNS options being delivered?
**Expected results as a baseline:** PC1 at 192.168.1.11 means DHCP is behaving as planned. An address from a different range, 169.254.x.x or no address means the exchange failed somewhere and the checklist above is followed.
