# 3. ISP Router as DHCP Server
 
The ISP-Router represents the upstream provider. It has a static address and leases an address to the Edge-Router. Full configuration: [`configs/isp-router.cfg`](../configs/isp-router.cfg).
 
Requirements for the ISP-Router:
 
1. A static IP address on the interface facing the Edge-Router.
2. An enabled interface.
3. A DHCP pool of addresses it may lease.
4. An exclusion so its own address is never leased.
5. A default gateway and DNS server to advertise.
6. A saved configuration.
The ISP-Router is not a DHCP client. It is configured manually and then assigns addresses to others.
 
## 3.1 Enter configuration mode
 
In Packet Tracer, opened the **CLI** tab on ISP-Router and pressed Enter.
 
```
Router> enable
Router# configure terminal
Router(config)#
```
 
| Mode | Prompt | Purpose |
|---|---|---|
| User EXEC | `Router>` | Basic checks only |
| Privileged EXEC | `Router#` | `show` commands, troubleshooting, saving configuration |
| Global configuration | `Router(config)#` | Configuration changes |
| Interface configuration | `Router(config-if)#` | Settings for one interface |
| DHCP pool configuration | `Router(dhcp-config)#` | Settings for one DHCP pool |
 
An "invalid command" error is often a command entered in the wrong mode. For example, `ip address` is only accepted in interface configuration mode. The prompt shows the current mode.
 
## 3.2 Configure the WAN interface
 
```
ISP-Router(config)# interface gigabitEthernet 0/0/0
ISP-Router(config-if)# ip address 200.1.1.1 255.255.255.0
ISP-Router(config-if)# no shutdown
```
 
| Command | Effect |
|---|---|
| `interface gigabitEthernet 0/0/0` | Selects the interface. IP addresses belong to interfaces, not to the router as a whole. |
| `ip address 200.1.1.1 255.255.255.0` | Places the interface in 200.1.1.0/24. Usable hosts are .1 to .254. |
| `no shutdown` | Enables the interface. Without it the address, cable and DHCP configuration have no effect. |
 
## 3.3 Exclude the router's own address
 
```
ISP-Router(config)# ip dhcp excluded-address 200.1.1.1
```
 
200.1.1.1 belongs to the router. Without the exclusion the server could offer it to the Edge-Router, producing a duplicate address and intermittent connectivity. With it excluded, the first address available is 200.1.1.2.
 
A range can be excluded with two addresses (`ip dhcp excluded-address 200.1.1.1 200.1.1.10`). Only .1 was needed here.
 
Exclusions are configured before the pool so infrastructure addresses are protected from the start.
 
## 3.4 Create the DHCP pool
 
```
ISP-Router(config)# ip dhcp pool ISP-POOL
ISP-Router(dhcp-config)# network 200.1.1.0 255.255.255.0
ISP-Router(dhcp-config)# default-router 200.1.1.1
ISP-Router(dhcp-config)# dns-server 8.8.8.8
```
 
| Command | Effect |
|---|---|
| `ip dhcp pool ISP-POOL` | Creates the pool. The name is arbitrary; this one describes its purpose. |
| `network 200.1.1.0 255.255.255.0` | Subnet the pool leases from |
| `default-router 200.1.1.1` | Default gateway sent to the client |
| `dns-server 8.8.8.8` | DNS server sent to the client |
 
When the Edge-Router sends a DHCPDISCOVER, the ISP-Router offers 200.1.1.2 with mask 255.255.255.0, gateway 200.1.1.1 and DNS 8.8.8.8.
 
## 3.5 Save the configuration
 
```
ISP-Router(config)# end
ISP-Router# write memory
```
 
`copy running-config startup-config` does the same. The running configuration is in RAM and is lost on reload unless saved to the startup configuration in NVRAM.
 
## 3.6 Verify before configuring the client
 
| Command | Expected result |
|---|---|
| `show ip interface brief` | GigabitEthernet0/0/0 has 200.1.1.1 and status/protocol `up up` |
| `show running-config \| section dhcp` | The exclusion and the `ISP-POOL` definition |
| `show ip dhcp pool` | `ISP-POOL` exists with zero leases |
| `show ip dhcp binding` | Empty, because no client has requested an address yet |
 
Interpreting `show ip interface brief`:
 
| Status / protocol | Meaning | Action |
|---|---|---|
| `up` / `up` | Interface enabled and link layer working | None |
| `administratively down` / `down` | Interface not enabled | Enter `no shutdown` |
| `up` / `down` | Interface enabled, Layer 2 or physical problem | Check the cable and the connected device |
