# 6. Troubleshooting
 
Three problems occurred while building the lab. In each case the interface state or the server side was checked before any DHCP setting was changed.
 
## Problem 1: PC did not receive an IP address
 
**Symptom:** After configuring the pool on the Edge-Router, `ipconfig` on PC1 showed `0.0.0.0`.
 
**Cause:** `no shutdown` had not been entered on the Edge-Router LAN interface (FastEthernet 0/1), so the interface was administratively down and could not receive the DHCP requests.
 
**Fix:**
 
```
Edge-Router(config)# interface fastEthernet 0/1
Edge-Router(config-if)# no shutdown
```
 
PC1 then received an address.
 
**Takeaway:** Check interface state with `show ip interface brief` before assuming the DHCP configuration is wrong.
 
## Problem 2: Edge-Router did not receive an address from the ISP
 
**Symptom:** The Edge-Router WAN interface was configured with `ip address dhcp` and `no shutdown`. `show ip interface brief` showed the interface `up`/`up` but with no IP address.
 
**Cause:** The pool existed on the ISP-Router, but `no shutdown` had not been entered on its GigabitEthernet 0/0/0 interface, so nothing was available to answer the request.
 
**Fix:**
 
```
ISP-Router(config)# interface gigabitEthernet 0/0/0
ISP-Router(config-if)# no shutdown
```
 
The Edge-Router then received 200.1.1.2.
 
**Takeaway:** A client that gets no address can be caused by the server side. Check both ends: client configuration, server configuration, server interface state and the link between them.
 
## Problem 3: Address conflict on the first PC
 
**Symptom:** PC1 received 192.168.1.1 instead of 192.168.1.11. That address is already used by the Edge-Router LAN interface.
 
**Cause:** The pool was created without excluding addresses reserved for infrastructure, so the server was allowed to lease 192.168.1.1.
 
**Fix:**
 
```
Edge-Router(config)# ip dhcp excluded-address 192.168.1.1 192.168.1.10
```
 
On PC1, `ipconfig /release` followed by `ipconfig /renew` returned 192.168.1.11.
 
**Takeaway:** Define exclusions for routers, servers, printers and other static devices before the pool hands out addresses.
 
## Systematic approach
 
Work from the bottom up and change one thing at a time:
 
1. Is the interface up?
2. Does the PC have an IP address?
3. Are the mask and default gateway correct?
4. Is DHCP working (pool, exclusions, bindings)?
5. Can the PC reach the router?
6. Can the router reach the next network?
